## Six-state migration and transaction boundaries

Legacy Normal, Golden, and Rainbow keys map directly; ambiguous historical Shiny maps to Normal Shiny only when no exact combined Shiny state exists. Inventory backfill then repairs exact owned states. Hatch batches deduplicate against their starting snapshot, while successful machine conversion writes both canonical and legacy keys and uses only the canonical key for `isNewDiscovery`; rollback restores each prior key value with inventory identity, and ordinary failed rolls add no discovery.

## Live state supersedes remote snapshots

Committed hatch and machine outputs carry the variant/Shiny fields consumed by `PetDex.recordPet`. A newly recorded result increments `_petIndexRefreshGeneration` before older callbacks can replace the cache. Refreshes additionally require a current generation, enabled index, successful invocation, and valid projection, so rate limits and transport failures cannot clear progress.

## Complete-place determinism and independent provenance

Two generator and rbxmk runs must match byte-for-byte. RBXL is converted back to XML, rechecked for all 77 exact script sources, compared as a complete normalized semantic tree, and converted to RBXL again with byte equality required. Runtime inventory fails closed on unsupported layouts, symlinks, invalid UTF-8, CRLF, unsafe CDATA, and unsupported model JSON.

`verify_release_artifacts.py` imports no builder code and independently reconstructs the artifact and manifest contracts. The tracked release passes its verifier and the builder's `--check`; replacement and directory-fsync fault matrices also restored the prior complete release set without staging residue.

## Verification evidence

The tree passes 345/345 Lua tests, 77/77 generated source parity, Python syntax checks, independent provenance verification, `git diff --check`, and the locked rbxmk 0.9.1 deterministic build check, including complete semantic and binary roundtrips.
