# Server-authoritative Movement Speed and owner-bound Magnet pickups

QOF-12 adds strict Movement Speed and Magnet entitlement chains without changing schema V7 or reinterpreting legacy IDs. Movement composes quest, mastery, shop, and tree multipliers behind one server authority; destructible currency is resolved once into owner-bound transient pickups and credited exactly on collection, timeout, or leave. The formulas, caps, contribution allocation, exact-credit boundary, generic tree data, and generated-place source parity are covered by focused tests. The change is not ready to merge because the server artifact still executes a deleted movement helper, and pending rewards are not protected through every leave/shutdown failure path.

Watch for: **confirmed / medium** runtime error from the stale `applyWalkSpeedBuffs` loop; **likely / high** shutdown saves racing ahead of pickup settlement; **confirmed / high** failed leave settlement deleting an uncredited reward; **confirmed / low** contradictory release documentation and untracked Python cache artifacts.

**Verdict**: NEEDS_CHANGES

## High-level view

Movement Speed uses the required `min(128, 16 × Quest × Mastery × Shop × Tree)` model and restores the authoritative value across character lifecycle and source changes. The old five-second scheduler remains in `Main.server.lua` and calls a helper removed by this diff; the byte-identical generated place contains the same error (**confirmed / medium**).

Magnet uses `min(32, 8 × Tree × DropMagnet)`, and destructible bonuses are resolved before pickup creation so settlement cannot reroll or reapply them. Owner identity, position, amount, and currency stay server-owned, and `CollectCurrency` remains outbound-only. Proximity, timeout, and successful leave claims are idempotent, but failed leave credit removes the pending record (**confirmed / high**).

The pickup service is initialized before zone rewards and settled before normal profile release, but it has no shutdown-wide settlement path. The existing `BindToClose` saver can snapshot and release profiles independently of `PlayerRemoving`, so pending pickup value can miss the final persisted snapshot (**likely / high**).

The new tree nodes occupy distinct hex coordinates, preserve the `Eggs II` roots and strict chains, and expose only canonical IDs. Pure-Lua tests pass 147/147 and generated-place verification confirms all 66 runtime sources are byte-identical, but neither check executes `Main.server.lua`; the documentation simultaneously says generated artifacts are pending and complete (**confirmed / low**).

## Movement authority is followed by a dead legacy scheduler

`MovementService` owns the required composed formula, binds only after profile load, disconnects stale character generations, and reconciles purchases, expiry, quest changes, and competing property writes. The final task in `Main.server.lua:848-856` was not removed with the old helper. Once a player is present, line 854 calls undefined global `applyWalkSpeedBuffs`, raises, and terminates that task (**confirmed / medium**). `BATTLE_PETS.rbxlx:1569-1573` embeds the same stale call. Remove the legacy task entirely and add a server-entry smoke/static test so service extraction cannot leave unresolved references.

## Exact pickup claims lose value on a failed leave credit

Successful settlement changes a record from pending to claiming before exact credit and removes authority before non-critical quest/UI callbacks. Combined with owner/range checks and server-only reward fields, that makes ordinary proximity, timeout, and duplicate claims exact and idempotent.

`PickupService.onPlayerRemoving` settles each record, but lines 297-299 call `removeRecord(record)` whenever `creditResolvedReward` returns false (**confirmed / high**). That destroys registry authority and the visual without crediting or preserving the amount, contradicting the leave guarantee and the retry behavior used for ordinary claims. Keep failed records recoverable until a guaranteed persistence fallback commits the exact amount, and test failed-credit leave settlement rather than only successful leave.

## Shutdown saving does not settle transient rewards first

Normal removal orders pickup settlement before `DataService.onPlayerRemoving`, but shutdown takes another route. `DataService.bindToClose` saves and releases every cached profile from its own callback (`DataService.lua:304-310`), while the new `PickupService` exposes only `onPlayerRemoving` (`PickupService.lua:282`) and Main registers no pre-save shutdown settlement (**likely / high**).

If shutdown snapshots first, later settlement mutates only the in-memory profile after the final snapshot; a second save can also lose session ownership because the first save released the lock. Add a settle-all/pre-save hook to shutdown and test pending rewards through that ordering.

## Verification claims omit the failing server entry point

The 147-test suite covers the new services, and generated-place verification confirms source parity, but neither executes `Main.server.lua`: `tests/run_tests.lua:125-130` loads service specs, while `tests/verify_generated_place.py:90-123` compares serialized bytes (**confirmed / low**). Add an entry-point smoke/static check; byte equality alone reproduces source defects in the artifact.

The status at `docs/QOF-12-speed-magnet-entitlements.md:3` says generated-place and binary validation are pending, while lines 78-79 say generator execution, byte-exact parity, and final inventory are complete (**confirmed / low**). Update the status to one truthful state after fixing and regenerating the artifact. The working tree also contains `tests/__pycache__/verify_generated_place.cpython-39.pyc` and `tools/__pycache__/generate_rbxlx.cpython-39.pyc`; remove these unrelated generated files before staging (**confirmed / low**).
