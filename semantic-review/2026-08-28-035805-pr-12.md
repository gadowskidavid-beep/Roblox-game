# Server-authoritative Movement Speed and Magnet pickup entitlements

QOF-12 activates canonical Movement Speed and Magnet upgrade chains without changing profile schema V7 or reusing legacy IDs. Movement composition moves behind one server authority, while world-breakable currency is resolved once into owner-bound transient pickups and credited on proximity, timeout, leave, or shutdown. The current pass fixes the earlier stale Main scheduler and adds pre-save settlement plus an exact cached-profile fallback. The only remaining finding is a non-blocking integration-test gap around the new ZoneService reward handoff.

**Verdict**: APPROVED

## High-level view

`MovementService` is now the sole production writer of `Humanoid.WalkSpeed`. It composes Sprinting, FasterRunning, the timed shop multiplier, and the contiguous tree entitlement, clamps the result to 16–128, and reasserts it across character and entitlement lifecycle changes.

World destructibles no longer credit currency at destruction. `ZoneService` snapshots contributor shares and reward bonuses once, `PickupService` owns the immutable amount and owner, and collection performs one exact bonus-free credit; there is no inbound pickup remote or client-supplied amount, position, owner, or radius.

Main initializes pickup authority before ZoneService can route rewards, binds movement only after profile load, settles pickups before normal profile release, and passes a settle-all hook into DataService before shutdown snapshots. Failed ordinary credits remain pending, while leave/shutdown can commit the same resolved amount directly into the cached profile before the releasing save.

The 150 Pure-Lua tests, 81-file Luau compilation, 50 JSON/3 Python/1 XML parse checks, and generated-place verifier all pass. The verifier confirms 66 byte-identical runtime sources and statically checks the critical Main wiring, but the changed ZoneService finalizer and queue/fallback bridge are not exercised by a test (**confirmed / low**).

## Resolved rewards cross one exact-credit boundary

`ZoneService` resolves random drops, contributor allocation, the Coin Potion multiplier, quest/mastery multipliers, and DropCloner before creating a pickup. The pickup record—not replicated Part attributes—is authoritative for owner, currency, amount, position, expiry, and state. Registry authority is removed before quest/UI notifications, so a successful credit cannot become claimable again if a non-critical callback fails.

The pending cap settles the oldest pickup before admitting another and falls back to immediate exact credit if pickup creation cannot preserve the reward. Both pet and Crit-QTE destruction call the same finalizer, which also clears every pet target and crit window before respawn scheduling.

## Leave and shutdown settle before profile release

Normal removal settles all owner pickups before `DataService.onPlayerRemoving`; shutdown invokes `PickupService.settleAllPlayers` before any parallel final save takes its snapshot. If the normal credit API returns false, settlement retries against the cached profile without reapplying bonuses; a second failure leaves registry authority intact rather than deleting uncredited value. This addresses the prior-pass leave and shutdown blockers.

## Zone destruction routing lacks an integration regression test

No test references `ZoneService._rewardContributors`, `_finalizeDestroyedDestructible`, or `queueResolvedCurrency` (**confirmed / low**). CurrencyService and PickupService are tested independently, but those tests would not catch a ZoneService regression that credits immediately, applies bonuses twice, skips one destruction path, or misses the direct-credit fallback. Add a focused ZoneService test that destroys one target through each attack path and asserts unchanged balance before pickup, one immutable queued amount, and one fallback credit when pickup creation fails.
