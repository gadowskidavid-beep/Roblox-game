# Retrying profile settlement and shared pet-mutation leases

The follow-up replaces global shutdown settlement with per-profile retry records, binds retained profiles to their original Player instance, and moves hatch, machine, enchant, and direct pet mutations behind an opaque per-player lease. The exact V1 enchanting response validator now rejects noncanonical prices, outcome order/content, extra keys, and metatables. The lifecycle work is not yet safe to ship because mutation admission remains open while a profile is departing or being saved, and shutdown retries stop well before their advertised deadline. The checked-in place also predates the latest EggService source and fails byte-parity verification.

Watch for: **confirmed — CRITICAL:** a remote mutation can start after leave settlement has been declared complete and race the releasing save; **confirmed — HIGH:** unresolved shutdown workers stop after roughly 10 seconds despite a 25-second deadline; **confirmed — HIGH:** `BATTLE_PETS.rbxlx` is stale and embeds an older `EggService.lua`.

**Verdict**: NEEDS_CHANGES

## High-level view

DataService now keeps one retryable record per cached profile, preserves the exact departing Player reference, and isolates shutdown workers by user ID. The prior global-owner coupling and unsafe rejoin reuse are addressed, but settlement is not an admission barrier: the shared PetService lease can still be acquired after `PlayerRemoving` starts or while the final DataStore write is yielding.

PetService covers the requested direct mutation APIs, and Egg, Machine, and Enchant pass their existing lease through commit and rollback instead of reacquiring it. Opaque lease identity and inventory incarnations prevent a stale cleanup from releasing a newer owner, while failed transaction restores remain retained for later cleanup.

Shutdown creates independent profile workers, but the fixed 100-pass loop with a 0.1-second delay abandons a continuously unresolved profile after about 10 seconds. This leaves roughly 15 seconds of the configured shutdown budget unused and is not deadline-based retry behavior.

The pure client validator matches the six canonical outcomes and exact 500-Diamond/one-slot contract, with adversarial coverage for altered prices, order, extra fields, and metatables. The pure Lua suite passes 331/331 and all 102 Lua files compile, but generated-place parity fails against the latest EggService source.

## Departure settlement does not close mutation admission

**Confirmed — CRITICAL.** `DataService.onPlayerRemoving` registers the pending profile and considers owner cleanup complete once Egg, Machine, Enchant, and Pickup report settled (`src/ServerScriptService/Main.server.lua:960-984`; `src/ServerScriptService/Services/DataService.lua:315-337`). Neither that transition nor `DataService.getPlayerData` closes the shared pet-mutation boundary: the old Player instance continues to receive its cached profile (`DataService.lua:225-230`), and `PetService.beginInventoryMutation` checks only whether another lease currently exists (`PetService.lua:83-99`). The direct Equip, Unequip, Favorite, Delete, Bulk Delete, and legacy Hatch remotes therefore remain admissible during departure; those wrappers enter through `PetService.lua:626-642`, `742-746`, `786-790`, `835-839`, `878-882`, and `939-943`.

The same hole affects Egg, Machine, and Enchant for a departing player because their `_shuttingDown` flags are global shutdown gates, not per-profile departure gates. A concrete bad interleaving is:

```
PlayerRemoving cleanup says "settled"
        |
DataService snapshots profile and UpdateAsync yields
        |
late remote acquires PetService lease and mutates cached profile
        |
old snapshot releases session; cache is cleared
```

The mutation is acknowledged in memory after the persisted snapshot was taken, then discarded when the releasing save completes. The service-specific transaction registries cannot repair this because `record.settled` prevents another settlement pass before save retries, and direct PetService CRUD is not represented in any of those registries.

Departure must atomically close central lease admission before owner settlement begins, and the close state must remain attached to that exact profile/Player generation through successful save-and-release. Shutdown needs the corresponding global admission close for all PetService mutations, not only Egg/Machine/Enchant. Settlement should also verify the central lease itself is empty before marking the profile settled. Add a deterministic test that pauses the releasing save after snapshot creation and attempts Delete/Hatch/Equip/Favorite plus Enchant/Machine admission; every path must fail closed and the persisted snapshot must equal the final acknowledged state.

## Shutdown workers abandon the remaining deadline

**Confirmed — HIGH.** The worker deadline is calculated from the configured 25-second timeout at `DataService.lua:393`, but every profile worker is also capped by `_shutdownMaxPasses = 100` and sleeps 0.1 seconds after an unresolved pass (`DataService.lua:32`, `400-402`). A fast unresolved owner therefore exits after about 10 seconds even though the shared deadline has approximately 15 seconds remaining. If that owner becomes settleable later in the existing shutdown budget, no worker remains to save and release it.

Use the deadline as the production termination condition and keep any pass limit only as a test seam that cannot shorten the real budget. Coverage should advance a controlled clock beyond ten seconds, resolve one owner before the 25-second deadline, and prove that profile is saved exactly once while a permanently unresolved profile remains held and unrelated profiles still release.

## Generated place omits the latest Egg lifecycle code

**Confirmed — HIGH.** `python3 tests/verify_generated_place.py` fails at `tests/verify_generated_place.py:723-725` with `generated source bytes differ from src/ServerScriptService/Services/EggService.lua`. The XML contains the expected 74 ModuleScripts, one Script, and one LocalScript, so this is source drift rather than a missing hierarchy node; shipping the place would ship an older Egg transaction implementation than the reviewed source. Regenerate `BATTLE_PETS.rbxlx` only after the lifecycle fixes, then rerun byte-parity verification.

**Confirmed — LOW.** The release documentation states “73 ModuleScripts + 1 Script + 1 LocalScript = 75” at `README.md:183`, while the verifier contract and actual generated hierarchy are 74 + 1 + 1 = 76 (`tests/verify_generated_place.py:43`). Correct the documentation together with regeneration so the advertised artifact contract matches the enforced one.
