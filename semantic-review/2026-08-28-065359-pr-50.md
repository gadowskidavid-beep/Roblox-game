# Zone 3 Gold Machine with server-owned conversion authority

QOF-16 activates only the Zone 3 Gold Machine and replaces the free legacy conversion route with a generic, rate-limited `UseMachine` transaction backed by private world validation. Gold admission, payment, pet consumption, RNG, rollback, and post-commit quest progress are server-owned; Rainbow remains gated before profile or economic work. The generated place is source-complete, but the client session lifecycle and mixed-version remote transition are not safe enough to ship yet. Review decision: **CHANGES_REQUESTED**.

Watch for: **confirmed** old clients block during startup when `ConvertToGoldenPet` disappears; **confirmed** the inventory close path leaves a machine session live; **confirmed** delayed result cleanup can destroy a newer session's overlay; **confirmed** two configured prompt properties are omitted from the claimed exact integrity check; **confirmed** current client tests are source-string assertions and miss these state transitions.

**Verdict**: NEEDS_CHANGES

## High-level view

The server topology is split between `ZoneService`, which owns exact station references and live unlock/distance checks, and `MachineService`, which owns the economic snapshot and conversion transaction. `Main.server.lua` installs world authority only after zone initialization returns successfully, so a failed world build leaves `UseMachine` present but unusable.

The global kill switch and Gold's per-definition gate are enabled, while Rainbow's gate rejects before token validation, profile access, RNG, pet mutation, or currency work. The former free `ConvertToGoldenPet` handler is no longer routed publicly.

The client delegates selected IDs without optimistic economy changes and rejects in-flight responses after cancellation. The broader UI lifecycle has no equivalent generation ownership: closing inventory does not cancel the session, and delayed result cleanup operates on whichever overlay is current three seconds later.

The remote rename is not rolling-compatible. Any old client paired with the new remote set waits indefinitely for `ConvertToGoldenPet` near the beginning of `Main.client.lua`, preventing the rest of the client runtime from initializing rather than merely disabling the old conversion button.

The executable service/station tests cover the transaction and server authority, and the supplied validation claims reproduce. The new client coverage only searches source text, so it cannot detect prompt-hidden races, close/reopen behavior, retry ownership, mixed-version startup, or a world-init failure integration path.

<details><summary>Details</summary>

## Private station authority omits part of its own prompt contract

The private registry and validator reject copied station identity and recheck Zone 3 unlock plus server-side HumanoidRootPart distance. However, the prompt is created with `HoldDuration = 0` and `RequiresLineOfSight = false` at `ZoneService.lua:111-113`, while the integrity predicate at `ZoneService.lua:164-173` checks neither property (**confirmed**). A server-side mutation can make the legitimate prompt contract materially different while remote admission still treats the station as intact; add both properties to the predicate and tamper tests for every configured prompt field.

## Inventory close leaves station selection active

The Pet Inventory close button only calls `toggleScreen("PetInventory")` at `UIController.lua:1301-1303`; screen navigation cancels hatch state but never invokes the registered Gold cancellation callback. Consequently `_goldMachineSessionActive`, `_multiSelectMode`, the selected IDs, active prompt, machine ID, and token survive closing the visible inventory until `PromptHidden`, overlay Cancel, or another explicit machine close occurs (**confirmed**). Reopening inventory while still near the prompt restores the hidden session and action without a fresh station interaction.

Treat closing or navigating away from Pet Inventory as a machine abort, or make the session an explicit modal whose close button delegates to `closeGoldMachineSession`. Add behavioral coverage that verifies close, PromptHidden, overlay Cancel, and screen replacement clear the same state exactly once.

## Delayed result cleanup can delete a newer overlay

After a business result, `showGoldMachineResult` schedules cleanup for three seconds later, but the closure reads `self._goldMachineOverlay` at execution time rather than retaining and checking the overlay/session that produced the result (`UIController.lua:2290-2297`). If PromptHidden closes that result and a new prompt session creates another confirmation overlay before the timer fires, the old timer destroys the new overlay and clears its result/button references (**confirmed**). The in-flight operation token in `Main.client.lua` does not protect this later UI timer.

Capture the completed overlay and only clear fields when `self._goldMachineOverlay == completedOverlay`, or carry the machine session generation through every delayed callback. Exercise close/reopen and result/retry interleavings with fake timers so an earlier generation cannot mutate a later one.

## Remote replacement stalls mixed-version clients

The new server creates `UseMachine` and no `ConvertToGoldenPet`, while the base client blocks at `Remotes:WaitForChild("ConvertToGoldenPet")` before the rest of startup. During any mixed-version window, an old client connected to the new remote set waits indefinitely and loses the entire client runtime, not only Golden conversion (**confirmed**). The published PR branch currently contains the server-only commit while its paired client/place changes remain uncommitted, making that mismatch easy to exercise outside the final local artifact.

Keep a deprecated `ConvertToGoldenPet` RemoteFunction for a compatibility window with a fail-closed handler that performs no mutation, then remove it after old clients are no longer possible. This preserves the no-bypass requirement without turning remote discovery into a startup deadlock; add a mixed-version startup contract test.

## Source assertions miss Gold session and startup failures

`MachineClient.spec.lua` verifies string presence and absence but never instantiates `UIController`, emits `PromptTriggered`/`PromptHidden`, advances delayed tasks, retries a failed request, or closes Pet Inventory (**confirmed**). `MachineStation.spec.lua` executes the private validator, but its prompt tamper case changes only `Enabled` and parentage; `Main.server.lua` world-init failure and validator non-installation are not executed end to end.

Add stateful client tests for close/cancel/retry/stale-generation behavior, prompt-property mutation cases for every configured field, a mixed-version remote fixture, and an entry-point test proving that a thrown or non-function `ZoneService.init` result leaves machine activation unavailable. Source-string checks prove wiring text, not Roblox event semantics.
