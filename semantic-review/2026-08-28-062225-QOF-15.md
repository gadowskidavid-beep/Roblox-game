# Dormant Gold and Rainbow machine transaction foundation

QOF-15 adds an internal Gold/Rainbow transaction coordinator and PetService conversion primitives without exposing a playable machine surface. Business RNG failures consume payment and inputs; technical failures restore the pending debit and pet mutation. The revision closes all five requested invariants from the prior review with direct adversarial coverage. One non-blocking documentation sentence still overstates discovery snapshot restoration.

Watch for: **confirmed** (non-blocking) documentation drift between “exact prior” discovery restoration and the implementation's intentional preservation of unrelated post-mutation progress; no runtime blocker remains.

**Verdict**: APPROVED

## High-level view

`MachineService` remains doubly fail-closed: `BalanceConfig.Machines.RuntimeEnabled` is false, and Main injects no activation validator. No machine remote, station, prompt, result event, controller, or UI enters the runtime surface, while `ConvertToGoldenPet` still routes to the unchanged legacy implementation.

Each attempt resolves a private scalar definition snapshot and gives future world authority a separate `{ machineId, zoneId }` facts object. Plain-list admission precedes length, iteration, and indexing, so metatable-bearing input cannot execute caller-controlled metamethods in MachineService or the direct PetService primitive.

After mutation-free preparation and one silent debit, `roll <= chance` selects the outcome. Both outcomes consume every input and the configured price; success creates one canonical Gold or Rainbow pet, preserving Shiny by OR. Currency commits before inventory replication and successful-Gold quest progress.

Pet commit rejects discovery identity or content drift before inventory mutation. Technical rollback restores ordered pet identity and conditionally reverses only its discovery key; unrelated keys and replacement tables survive, and a second rollback is inert.

Independent verification passed all 217 tests, compiled every changed Luau source/spec, passed `git diff --check`, and verified byte-exact parity for all 68 generated Place sources. The verdict also follows direct source tracing of authority, commit ordering, and rollback ownership rather than relying on those checks alone.

## Private economics snapshot and disposable activation facts

`resolveMachine` copies machine ID, zone, variants, currency, and amount into a transaction-private table (`MachineService.lua:30-52`). The activation callback receives a separately allocated facts DTO containing only machine ID and zone (`MachineService.lua:175-188`), so callback writes cannot change the variants, price, result metadata, or definition consumed by the current transaction. The adversarial test mutates every plausible facts field while the transaction still charges 750 Diamonds and produces the configured Gold result (`MachineService.spec.lua:559-583`). This closes the previous live-definition authority leak.

The runtime gate rejects attempts before request data is interpreted (`MachineService.lua:274-277`). If a future QOF enables it, a missing validator, callback error, or result other than literal `true` still denies without payment. Main deliberately omits validator injection (`Main.server.lua:193-196`).

## Plain-list admission without caller metamethod execution

Both conversion entry points reject a non-nil metatable immediately after confirming the value is a table. MachineService then counts keys with raw `next`, checks `rawlen`, and copies with `rawget` (`MachineService.lua:54-91`); PetService repeats the boundary before inventory admission (`PetService.lua:722-756`). No `#`, `pairs`, `ipairs`, or ordinary index access occurs first.

The regression invokes both APIs with throwing `__len`, `__pairs`, and `__index` metamethods and observes zero metamethod calls (`MachineService.spec.lua:585-610`). This closes the escaped pre-`xpcall` failure and hostile direct-call path from the prior review.

## Discovery divergence and transaction-owned rollback

Preparation captures discovery table identity and its boolean map. Commit compares both directions and rejects a replacement table or changed key/value set before setting `mutationStarted` or touching inventory (`PetService.lua:876-907`). The already-open debit then rolls back without removing the external discovery update.

After a successful pet mutation, prepared state records the write table, key, previous presence/value, written value, and whether the table was transaction-created (`PetService.lua:946-966`). Rollback restores that key only while the profile still references the same table and the key still contains the transaction's value; it never reinstalls the old full snapshot. A foreign key and a replacement table survive, while an empty table created solely for the rolled-back key is removed. Clearing mutation ownership makes a repeated call inert (`PetService.lua:972-1010`). Tests cover content and identity divergence, same-table foreign progress, replacement after mutation, and direct double rollback (`MachineService.spec.lua:612-700`).

The document still says technical rollback restores the exact prior discovery shape/content (`docs/QOF-15-machine-transaction-foundation.md:31`). That is true only without foreign progress; the documented contract should reflect conditional key-owned restoration.

## Paid business failure and technical atomicity

Gold and Rainbow remain zones 3 and 6, Normal→Golden and Golden→Rainbow, priced at 750 and 2,500 Diamonds, with exact 13/26/39/50/63/88/100 percent chances. BalanceConfig validation pins every field and rejects unknown chance indices. `roll <= chance` guarantees seven inputs (`MachineService.lua:220-228`).

The debit opens only after preparation. Pet commit removes selected inputs for both outcomes and adds an output only on success; currency commit follows (`MachineService.lua:202-259`). A finite roll above chance therefore commits cost and input consumption without output. Invalid RNG and dependency faults instead restore the pending debit and started pet mutation; failed restoration is reported as `Conversion rollback failed` rather than as safe recovery.

Canonical pet helpers derive output name, rarity, damage, discovery key, and compatibility mirrors. `anyShiny = anyShiny or pet.shiny == true` preserves independent Shiny state across inputs (`PetService.lua:808`), including Rainbow conversion. Inventory replication and the Gold-only `goldenPetsConverted` increment occur after currency commit and are protected (`MachineService.lua:253-270`); Rainbow, failed rolls, and rolled-back transactions do not advance that quest.

## Dormancy, legacy isolation, and generated artifact

Main only requires/initializes MachineService, injects QuestService, and clears locks on removal. `ConvertToGoldenPet` still calls `PetService.convertToGoldenPet` (`Main.server.lua:475-501`), whose legacy body is unchanged against HEAD. No machine remote name, activation wiring, station, prompt, event, client script, or UI was added.

The pure-Lua suite passed 217 tests with zero failures. Luau compilation passed for BalanceConfig, Main, PetService, MachineService, the machine spec, and the runner. The generated Place contains 66 ModuleScripts, one Script, and one LocalScript, with all 68 embedded sources byte-identical to the repository.
