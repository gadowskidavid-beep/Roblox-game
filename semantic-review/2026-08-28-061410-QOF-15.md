# Dormant Gold and Rainbow machine transaction foundation

QOF-15 adds canonical Gold/Rainbow definitions, a MachineService transaction coordinator, and PetService conversion primitives while leaving machines publicly disabled. Failed rolls are paid, input-consuming business outcomes; technical failures use silent currency and pet rollback, with inventory replication and Gold quest progress after commit. The generated place and focused tests move with the runtime code. Three code-level authority and rollback invariants still block the foundation.

Watch for: **confirmed** mutable machine definitions cross into activation code; **confirmed** metatable-bearing input can execute during strict validation; **confirmed** discovery rollback can overwrite progress made after preparation.

**Verdict**: CHANGES_REQUESTED

## High-level view

BalanceConfig owns exact prices, zones, variants, and the 13/26/39/50/63/88/100 percent chance curve. `RuntimeEnabled` remains false, Main installs neither an activation validator nor a machine remote, Rainbow shares the dormant path, and legacy `ConvertToGoldenPet` remains separately routed.

MachineService serializes its own attempts per player, checks zone and activation, begins one silent exact debit, and uses `roll <= chance`. Failed rolls consume the debit and every input; successful outputs preserve Shiny with OR semantics, and only committed successful Gold conversions advance the quest.

**Confirmed:** the activation validator receives the live canonical definition before MachineService reads conversion and price fields from it. **Confirmed:** request and PetService admission also accept metatable-bearing tables whose length metamethod executes before the protected transaction boundary.

**Confirmed:** inventory identity is revalidated before mutation, but discovery identity/content is not. Rollback restores the preparation-time discovery snapshot wholesale, erasing a discovery update or replacement made in the interim.

## Activation validation can rewrite canonical machine economics

`executeTransaction` checks `machine.zoneId`, then passes the live `machine` table to the callback (`MachineService.lua:149-157`). Afterward, that same table supplies `inputVariant`, `outputVariant`, currency, amount, and result metadata (`MachineService.lua:163-177`, `215-219`). **Confirmed:** future proximity code has unintended write authority over eligibility and price and can change `zoneId` after its only check. Snapshot and validate the definition before external code, then pass only the machine ID and immutable station facts.

BalanceConfig validates exact definitions at load time (`BalanceConfig.lua:634-681`), but does not freeze them afterward. The activation test returns only true/false, so definition mutation is not exercised.

## Dense-list validation executes hostile metamethods

Both admission layers check only `type(value) == "table"`, then use `pairs`, `#`, and indexed access (`MachineService.lua:42-65`; `PetService.lua:722-769`). **Confirmed:** `#petInstanceIds` invokes `__len`, which can throw, and MachineService validates before entering `xpcall` (`MachineService.lua:247-276`); malformed input therefore escapes as an invocation error rather than a controlled rejection. Reject metatables and copy through raw length/raw indexed reads, or run a strictly raw validator under protection, in both exported entry paths.

The malformed-list test (`MachineService.spec.lua:264-280`) uses ordinary tables. Not tested: throwing length/iteration/index metamethods, metatable-bearing dense arrays, or hostile direct calls to `PetService.prepareVariantConversion`.

## Discovery rollback can erase concurrent progress

Preparation captures the discovery table reference and full contents (`PetService.lua:836-842`), while commit revalidates only profile and inventory identity/content (`PetService.lua:865-895`) before writing the conversion key at line 917. Rollback later assigns the captured table back and clears/rebuilds it from the old snapshot (`PetService.lua:938-946`). **Confirmed:** a discovery added or a table installed after preparation is deleted by a later machine rollback. Add discovery revision/identity validation before mutation or record and reverse only the machine-owned key.

MachineService's player lock excludes other PetService/EggService mutation paths. Inventory replacement/reordering and selected-pet protection changes are rechecked, but discovery has no corresponding invariant. Existing rollback tests (`MachineService.spec.lua:405-464`) restore an unchanged snapshot; not tested: discovery mutation/replacement across prepare/commit, divergence before rollback, or a repeated direct rollback.

## Commit boundary and verification coverage

Currency commit precedes protected inventory replication and the successful-Gold-only quest call (`MachineService.lua:226-242`), so post-commit notification failures remain non-retryable. Locally handled failures clear transaction handles before returning, and pet rollback clears `mutationStarted`; a second currency rollback fails closed rather than crediting twice. **Confirmed coverage gap:** no test directly invokes rollback twice, despite this being an explicit lifecycle invariant.

The pure-Lua suite passes 211 tests, including exact chance boundaries, failed-roll consumption, Shiny Gold/Rainbow output, projected capacity, commit and rollback failures, lock reentry, and post-commit notification faults. The generated-place verifier passes with 66 ModuleScripts, one Script, one LocalScript, and byte-exact parity for all 68 runtime sources. Roblox Studio/live Luau execution remains pending, which is non-blocking for this review.
