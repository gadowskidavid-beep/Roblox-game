# Shop system, DataStore hardening, and quest/mastery buff wiring

This change adds a diamond-based shop with four items (Lucky Potion, Speed Potion, Auto-Hatch, Extra Equip Slot), replaces `SetAsync` with retrying `UpdateAsync` in DataService, adds a `deepMerge` for schema evolution, and wires remaining quest/mastery bonuses (Sprinting → walkspeed, CoinCollector → coin multiplier, BetterLuck → egg luck, FasterRunning → walkspeed). A central `applyWalkSpeedBuffs` function aggregates three multiplicative speed sources with a 5-second periodic refresh. Watch for: Lucky Potion buff is purchased but never consumed during hatching (confirmed); Auto-Hatch fires a client animation event but never triggers a server-side hatch (confirmed); Extra Equip Slot increments `shopPurchases.extraEquipSlots` but `getMaxEquipped` doesn't read it (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The shop introduces timed buffs stored in-memory (lost on restart, acknowledged in comments) and one permanent upgrade persisted in player data. Two of the four shop items — Lucky Potion and Auto-Hatch — have incomplete server-side wiring: they deduct currency and record state but the downstream systems never query that state. The Extra Equip Slot is fully persisted but the equip-limit function ignores it.

DataStore saves now retry with exponential backoff via `UpdateAsync`, and a `deepMerge` handles nested default fields on load. The `UpdateAsync` callback discards `oldData` (unconditional overwrite) — functionally equivalent to `SetAsync` but gains atomicity.

WalkSpeed aggregation multiplies three independent buff sources (quest Sprinting, mastery FasterRunning, shop SpeedPotion) and reapplies every 5 seconds for all players plus on character spawn and mastery purchase. The CoinCollector quest bonus routes through `UpgradeService.getUpgradeBonus` → `QuestData.Quests["CoinCollector"]` and multiplies coin drops.

## Lucky Potion has no downstream consumer

The shop item definition sets `buffType = "luck"` and `purchaseItem` stores an expiry in `_activeBuffs[userId].luck`. The accessor `ShopService.getShopMultiplier(player, "luck")` exists and would return `2` while the buff is active. But `PetService.hatchEgg` — the only place egg luck matters — never calls it. The variant roll multiplies `Config.RAINBOW_CHANCE` and `Config.SHINY_CHANCE` by `luckyMultiplier` derived solely from `UpgradeService.getUpgradeBonus(player, "LuckyEggs")`. The weighted-pool selection uses `LuckyEggs` + `BetterLuck` (mastery). Neither path queries the shop buff.

Fix: in the variant roll block, multiply `luckyMultiplier` by `ShopService.getShopMultiplier(player, "luck")` (requires passing ShopService into PetService or querying it in Main.server.lua before calling hatch).

## Auto-Hatch fires only a client event

```lua
-- ShopService._processAutoHatch (every 3s)
hatchEvent:FireClient(player, "auto")
```

`EggHatchStart` is a RemoteEvent the client uses to trigger the wobble animation. No `EggHatchResult` ever fires because no server-side hatch occurs. The player pays 500 diamonds for visual spam with no pet produced.

A real implementation needs to:
1. Determine which egg to hatch (player's current zone egg or a stored preference).
2. Call `EggService.hatchEgg(player, eggType)` on the server.
3. Fire `EggHatchResult` so the client completes the reveal.
4. Rate-limit to avoid flooding inventory (3-second interval without cost gating fills inventory fast).

## Extra Equip Slot disconnected from equip logic

```lua
-- ShopService.purchaseItem (permanent path)
data.shopPurchases.extraEquipSlots = (data.shopPurchases.extraEquipSlots or 0) + 1

-- PetService.getMaxEquipped (unchanged)
local function getMaxEquipped(player)
    local base = Config.MaxEquippedPetsBase  -- 3
    local bonus = PetService._upgradeService.getUpgradeBonus(player, "Friendship")
    return base + (bonus or 0)
end
```

Fix: add `(data.shopPurchases and data.shopPurchases.extraEquipSlots or 0)` to the return value of `getMaxEquipped`.

## WalkSpeed buff expiry lag

The 5-second poll means walkspeed lingers up to 5 seconds after a Speed Potion expires. The Sprinting bonus goes through `QuestService.getUpgradeBonus` while FasterRunning uses `MasteryService.getBuffBonus` and speed uses `ShopService.getShopMultiplier` — three different service entry points for what's effectively one formula. A future refactor toward a single "get all speed multipliers" helper would reduce this fragmentation.

## CoinCollector intermediate flooring

Both LuckyDrops and CoinCollector bonuses use `math.floor(finalAmount * bonus)` sequentially. At low coin values (1-2), intermediate flooring prevents the multipliers from compounding. Example: 1 × 1.1 = floor(1.1) = 1, then 1 × 1.1 = floor(1.1) = 1. Consider accumulating the multiplier product and flooring once at the end.
