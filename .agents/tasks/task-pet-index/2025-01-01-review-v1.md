# Pet Index (Collection Book) with first-discovery popup gating (v1)

Adds a per-player discovery-tracking system (`discoveredPets` dictionary in DataService) and a new client-side Pet Index UI that renders a 4x4 grid of all pets across all variants. PetService stamps discoveries on hatch (Normal) and golden conversion (Golden), and the "NEW PET!" overlay is now suppressed for pets the player has already seen. A new "I" nav button opens the index; opening it fetches the latest discovery map from the server.

**Verdict**: NEEDS_CHANGES

## Issues (4)

1. **`isNewDiscovery` persists in saved inventory** - The field is left on the pet table permanently. Either strip it after firing the client event or store it out-of-band so it doesn't inflate DataStore writes.
2. **No duplicate-hatch feedback** - When `isNewDiscovery` is false, the player sees nothing after the egg animation. Add a brief toast or a shortened confirmation so the player knows the hatch succeeded.
3. **Hardcoded pet list in UIController** - The index grid iterates `{"Buddy", "Whiskers", "Blaze", "Inferno"}` instead of reading `PetData.Pets`. Adding a pet to PetData won't update the index without a matching code change.
4. **Shiny/Rainbow never discoverable** - The server only marks Normal and Golden discoveries. Since Shiny and Rainbow acquisition mechanics don't exist yet, show them in the grid with a "Coming Soon" state rather than a plain lock that implies obtainability.
