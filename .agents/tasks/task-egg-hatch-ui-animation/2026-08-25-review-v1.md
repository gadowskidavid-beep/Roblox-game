# Full-screen UI egg hatch animation replacing 3D workspace Parts

The 3D egg hatch effect (Part + PointLight + particles in workspace) is replaced with a pure ScreenGui animation: dark overlay → egg shape wobbles → flashes rarity color → white flash → pet name/rarity text reveal → auto-dismiss fade. The approach eliminates camera manipulation and 3D object management in favor of frame-based UI elements animated with TweenService. The three old private helpers (`_spawnLightFlash`, `_spawnBreakParticles`, `_showPetReveal`) that created and destroyed workspace Parts are removed entirely.

Watch for: overlapping overlays when the UIController "NEW PET!" modal fires at t=3s while this animation is still showing (confirmed); no reentrancy guard if the server fires two rapid hatch events (confirmed); dead `eggPosition` parameter (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The animation runs five sequential phases (wobble → crack → break-flash → reveal → fade) inside a `task.spawn` coroutine. All UI instances are built upfront, the coroutine sleeps between phases, and the ScreenGui is destroyed at the end — but only if the coroutine runs to completion without a second invocation stomping on the first.

Two full-screen overlays sharing the name "EggHatchOverlay" coexist at t≈3s: the EffectsController's animation (DisplayOrder 50, still in its reveal-hold phase) and the UIController's static "NEW PET!" panel (DisplayOrder default 0, showing behind). The naming collision means any code that searches for this GUI by name will find an unpredictable one.

There is no guard against calling `showEggHatchAnimation` while a previous instance is still playing. If the server sends two `EggHatchResult` events within 5 seconds, two independent overlays stack — the screen gets progressively darker and two eggs wobble simultaneously.

The `eggPosition` parameter is still accepted but never read, since the animation is entirely screen-space. The caller in Main.client.lua still computes `hatchPosition` from HumanoidRootPart — that computation is now dead code too.

## Reentrancy and stacking overlays

```lua
function EffectsController:showEggHatchAnimation(eggPosition, resultPet)
    if not self._initialized then return end
    -- no guard here against concurrent calls
```

If the server fires `EggHatchResult` twice in quick succession (multi-egg purchase, network retry), two full-screen overlays exist simultaneously. Both have BackgroundTransparency=0.5 on their dark overlay, so the screen gets progressively darker and two egg shapes wobble on top of each other. Both coroutines will eventually destroy their own ScreenGui, but the user experience degrades.

The fix is a single boolean flag:

```lua
if self._isHatching then return end
self._isHatching = true
-- ... at end of coroutine:
self._isHatching = false
```

Or destroy any existing ScreenGui named "EggHatchOverlay" at the start. The flag approach is simpler and doesn't race against the UIController's identically-named GUI.

## Timing overlap with UIController:showEggHatch

The call site in Main.client.lua:

```lua
effectsController:showEggHatchAnimation(hatchPosition, petData)
-- fires UIController modal 3s later:
task.delay(3, function()
    uiController:showEggHatch(petData)
end)
```

The EffectsController animation takes ~5.1s total before cleanup (sum of all task.wait calls plus tween durations). The UIController panel appears at t=3s, while the reveal text is still showing. The pet name and rarity are displayed by both — the EffectsController as floating text, the UIController as a boxed panel with an OK button.

This creates redundancy: the player sees the pet name/rarity twice in overlapping GUIs. Given that the new animation already reveals the pet name and rarity prominently, the 3-second delay should be increased to match the animation duration (~5.5s), or `UIController:showEggHatch` should be removed entirely to avoid the double-reveal.

## Dead parameter and API surface

The function signature is `showEggHatchAnimation(eggPosition, resultPet)` but `eggPosition` is never referenced in the new body. The old implementation used it to position the 3D Part in world space. Now that the animation is screen-space, the parameter is meaningless. The caller in Main.client.lua still computes `hatchPosition` from HumanoidRootPart — that computation is now dead code too.
